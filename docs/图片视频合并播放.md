# 图片与视频合并播放器

工程 `prj/TF_MEDIA.al`，顶层 `rtl/tf_media_top.v`，器件 EG4S20BG256。
新生成的合并程序命名为 `release/TF_MEDIA.bit`，原图片和视频独立工程仍可单独编译。

## SD 卡和屏幕

FAT32 卡根目录同时放置原有 640×480、24 位 BMP 图片和 `VIDEO.RV`。
图片沿用原自动目录扫描规则。无声视频使用 RVF1（1–5 fps），带音频视频使用 RVF2（3–5 fps），
两者均为 640×480、RGB332，推荐 3 fps。音频说明见 [视频音频播放](视频音频播放.md)。
无需删除原有图片，无需格式化；MP4 文件不能直接播放，转换方法见 [视频播放](视频播放.md)。
5 秒动态彩条可通过 `python3 tools/make_video_demo.py release/VIDEO.RV --seconds 5 --fps 3 --audio` 生成。

HDMI_B 连接屏幕，屏幕单独按其硬件说明供电。输出仍为 640×480；720×720 原生面板是否
接收并缩放这个输入信号需实测，本版没有改为 720×720 输出。菜单与 GT911 I²C 触控现已接入源码；触控测试版及接线待确认项见 [触控开发](触控开发.md)。
RVF2 音轨通过 HDMI 输出，屏幕耳机口可接有源音箱；暂停、重播及循环同时控制音轨。
图片和旧 RVF1 文件静音，硬件出声效果仍需实测。

## 按键

默认进入图片模式；KEY1 全局复位也回到图片模式。

| 操作 | 图片模式 | 视频模式 |
|---|---|---|
| KEY1 | 复位回第一张，关闭轮播 | 复位回图片模式 |
| KEY2 | 下一张（保留原板程序行为） | 从头播放，解除暂停 |
| KEY3 | 上一张（保留原板程序行为） | 保留 |
| KEY4 短按并松手 | 开启/关闭图片轮播 | 暂停/继续 |
| KEY4 持续按住约 2 秒 | 切换至视频模式 | 切换至图片模式 |

长按达到门限即切换，只切换一次；继续按住或松手不会额外触发短按。
短按在消抖后的松手时生效。模式切换重新初始化读卡和 SDRAM，期间短暂黑屏，
图片从第一张开始且轮播关闭；视频从第一帧开始且未暂停。
不支持热插卡。图片轮播的间隔、方向拨码及中文提示保留。

图片模式数码管显示图片编号与总数；视频模式左边显示读取状态、右边显示目标帧率。
视频错误 10–15 的含义见 [视频播放](视频播放.md)。没有 VIDEO.RV 时仍可切回图片模式；
没有 BMP 图片时也可长按切换到视频模式。

## 下载和测试

1. 复制文件后执行 `sync` 并安全卸载 SD 卡，开发板断电插卡。
2. 上电，在 BitWriter 添加 `release/TF_MEDIA.bit`。
3. 选择 AL-LINK、PROGRAM_SRAM、1 MHz，点击 Run。不要选旧的 TF_IMAGE/TF_VIDEO 文件。
4. 确认图片显示，KEY2/KEY3 切图，短按 KEY4 验证轮播。
5. 长按 KEY4 约 2 秒，验证视频自动循环；短按验证暂停/继续，KEY2 验证重播。
6. 再长按 KEY4 回图片模式，重复切换，检查无错行、花屏或卡死。

SRAM 下载断电失效，需重新下载。首次验证不要直接固化 Flash。

## 构建与验证

```bash
TD_BIN=/你的TD安装目录/bin/td.sh bash prj/build_tf_media.sh
bash sim/run_media_tests.sh
bash sim/run_ui_tests.sh
bash sim/run_catalog_tests.sh
bash sim/run_video_tests.sh
```

共用一套读卡、SDRAM、帧 FIFO、HDMI 电路；两个文件读取器按模式复用接口，未使用的读取器
保持复位。模式先在各时钟域同步，媒体复位和启动等待确保模式稳定后才开始读写。
图片切图保持原启动/重试逻辑；模式切换和视频重播重置整个媒体通路。
BMP 写入时翻转行序，视频保持从上到下；旧独立工程使用原来的固定行序参数。

新增 RTL 用例覆盖消抖、松手短按、长按只切换一次、长按松手不暂停、视频重播、全局复位，
以及共用写侧的 BMP/视频全帧地址、第二缓存和写入中复位。GitHub Actions 已接入这些用例。
