# 合并播放器的 HDMI 音频

使用最新 `release/TF_MEDIA_SWITCH_FIX.bit`，SD 卡根目录使用带音轨的 **RVF2 VIDEO.RV**。
信号路径：SD 卡 → FPGA 音视频播放器 → HDMI_B → 显示屏耳机口 → 有源音箱或耳机。
本版实现 48 kHz 单声道音轨，左右声道发送同一份声音；图片模式和旧 RVF1 文件静音。
显示屏需能从 HDMI 提取音频，耳机口的实际出声效果仍需实板验证。

## 立即测试

本机 `release/VIDEO.RV` 已生成 5 秒、3 fps 的移动彩条和间歇 440 Hz 提示音。
原无声测试文件备份为 `release/VIDEO_SILENT.RV`（如果原文件存在）。
其他电脑可从仓库根目录执行：

```bash
python3 tools/make_video_demo.py release/VIDEO.RV --seconds 5 --fps 3 --audio
```

1. 用新生成的文件替换 SD 卡根目录的 `VIDEO.RV`。旧文件没有音轨，不能仅靠更新 bit 增加声音。
2. 执行 `sync` 并安全卸载 SD 卡，开发板断电后插卡。
3. 屏幕供电，HDMI_B 接屏幕，音箱/耳机接屏幕耳机口，检查屏幕及音箱音量和静音设置。
4. 上电，在 BitWriter 删除旧列表项，重新添加 `TF_MEDIA_SWITCH_FIX.bit` 下载：AL-LINK、PROGRAM_SRAM、1 MHz。下载后保持通电。
5. 同时按住 KEY4+KEY2 约半秒后松开两键，或只按住 KEY4 约 2 秒（新门限为 1 秒），进入视频模式，应看到动态彩条，并听到响半秒、静半秒的测试音。
6. 短按 KEY4 并松手：画面暂停且音频静音；再次短按从暂停处继续。
7. KEY2 从头播放并解除暂停；长按 KEY4 返回图片模式并静音。视频和音轨一起循环。

如果没有声音：先确认使用新 bit 和 RVF2 文件，画面正常且未暂停；再检查音量、HDMI 输入和耳机口。
可将同一屏幕连接有 HDMI 音频输出的电脑，确认屏幕能提取音频。
独立 `TF_VIDEO.bit` 只支持旧 RVF1 文件，不能用于本次有声测试。

## 转换自己的视频

电脑安装 ffmpeg 和 ffprobe，从仓库根目录执行：

```bash
python3 tools/convert_video.py input.mp4 release/VIDEO.RV --fps 3 --audio
```

画面保留比例并补黑边为 640×480、RGB332；音轨下混为单声道、重采样到 48 kHz 后压扩编码。
转换器通过 ffprobe 检查第一条音轨，没有音轨时输出静音块并提示。
音频短于画面时补静音，长于画面时截断；音轨时间戳由 ffmpeg 对齐到输入时间线零点。
转换失败不覆盖原输出。音频版支持 3/4/5 fps，建议先用 3 fps；1/2 fps 只支持无声 RVF1。
没有 `--audio` 时仍生成旧无声格式。也支持 `--raw-rgb24 --pcm16 audio.pcm`，
其中 PCM 文件必须是 48 kHz 单声道、有符号 16 位小端原始采样，不含 WAV 文件头。

## 同步与限制

每帧画面之后存放对应时长的音频，两个画面缓存与两个音频缓存使用相同缓存号。
读卡端等画面写入 SDRAM 完成且音频读完后，才发布完整帧；显示端在垂直消隐选帧，
待 SDRAM 读缓存就绪、首个可见帧开始时启动这一块音频。
上一块音频未播放完时不切新帧，也不允许写侧覆盖仍在播放的音频缓存。
暂停期间仍按 48 kHz 向 HDMI 发送零采样，但不推进音轨位置。

本版是低帧率功能验证播放器，音频采用 8 位 μ-law 压扩恢复为 PCM，再以 24 位接口发送，
不等同于 24 位无损录音。音轨为单声道，不保留立体声声场。
显示刷新和文件帧率不能完全整除，帧交界处可能出现短暂静音；SD 卡慢或供数不足时，
保留上一帧，当前音频块结束后静音等待下一帧。不会让音频持续跑在冻结画面前面，
但本版不保证连续无缝音频或电影播放器级的同步精度。

μ-law 编解码参考 [CPython audioop 实现](https://github.com/python/cpython/blob/v3.12.0/Modules/audioop.c)。
转换器全部 65,536 个 PCM16 输入值与本机 CPython audioop 比对一致；RTL 独立解码向量由
本机 audioop.ulaw2lin 生成，保存在 `sim/mulaw_pcm16.hex`。

## RVF2 文件布局

所有多字节整数小端；512 字节头部，其后重复 `307200 字节 RGB332 + 音频块`。
每个音频采样一个 μ-law 字节，音频块补 `0xFF` 至整扇区，补齐字节不参与播放。

| 头部偏移 | 字节数 | 内容 |
|---|---|---|
| 0 | 4 | ASCII RVF2 |
| 4 | 1 | 版本 2 |
| 5 | 1 | 画面格式 1：RGB332 |
| 6 | 1 | fps：3/4/5 |
| 8/10 | 各 2 | 宽 640、高 480 |
| 12 | 4 | 帧数 |
| 16 | 4 | 每帧画面 307200 字节 |
| 20 | 4 | 采样率 48000 |
| 24 | 4 | 每帧音频采样数：16000/12000/9600 |
| 28 | 4 | 每帧音频存储字节数：16384/12288/9728 |
| 32 | 4 | 音频格式 1：单声道 μ-law |
| 36–511 | 476 | 保留，写零 |

FAT32 单文件容量限制仍适用。文件长度校验包含全部音频块；参数无效、数据不足报状态 12，
音频区域簇链提前结束报 13，读卡或 SDRAM 超时报 14，错误含义沿用视频文档。
