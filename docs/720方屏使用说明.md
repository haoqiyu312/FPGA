# 原生 720×720 方屏播放器

本版工程 `prj/TF_MEDIA_720.al`，顶层 `tf_media_top`，器件 EG4S20BG256。
图片输入、视频输入、双帧缓存与 HDMI 有效显示区均为 **720×720**。
保留实板成功的 `release/TF_MEDIA_SW4_R2.bit`，需要旧版时下载该文件并使用原 640×480 素材。

## 使用

已上板验证的原生方屏 R2 固件为 `release/TF_MEDIA_720_R2.bit`。
压缩包包含固件、SD 卡素材、说明及校验记录；只有最终布线时序通过后才生成固件发布包。

1. 将包内 `sdcard` 目录中的 BMP 和 RV 文件复制到 FAT32 卡根目录；安全弹出后断电插卡。
2. BitWriter 选择 AL-LINK、PROGRAM_SRAM、1 MHz，下载已验证的 `TF_MEDIA_720_R2.bit`。
3. 文件菜单中 KEY2/KEY3 上下移动，短按 KEY4 打开选中的 BMP 或 RV 视频；播放时长按 KEY4 返回文件菜单。
4. 图片播放中 KEY2/KEY3 切换图片；视频播放中 KEY2 开关频谱、KEY3 开关字幕、KEY4 暂停/继续视频及声音。
   图片播放中 KEY4 短按暂停/继续轮播。KEY1 复位并重新扫描 TF 卡。
5. SW1 开启/关闭图片轮播；SW2 选择 5 秒或 10 秒间隔；SW3 选择正序/倒序；SW4 拨上隐藏播放状态文字，拨下显示，文件列表不受影响。
6. 图片中同时按 KEY2+KEY3 循环缩放：100%→50%→200%；KEY3 长按约 1 秒切换图片字幕。视频中同时按 KEY2+KEY3 也可切换字幕。

电脑转换素材：

```bash
# 默认等比留边；正方形原图可完整铺满。--fit cover 等比裁剪铺满。
/usr/bin/python3 tools/convert_image720.py input.jpg AD01.BMP

# 需要 ffmpeg；默认 1 fps，带音频时使用 12 kHz 单声道。
python3 tools/convert_media720.py input.mp4 COFFEE.RV --audio
# 裁剪铺满：
python3 tools/convert_media720.py input.mp4 VIDEO.RV --audio --fit cover
```

图片转换需要 Pillow，本机 `/usr/bin/python3` 已提供。旧的 640×480 文件需重新转换；
旧版 48 kHz 音轨 RVF2 也需转换为本版 12 kHz 音轨，不能直接只改文件名。
原生高分辨率输入可保留更多细节；低分辨率素材转换后增加的是插值像素。

## 显示与性能

- 48 MHz 像素时钟、50 MHz SDRAM 时钟。
- HDMI 输出 720×720 有效画面，总时序 940×768，刷新率约 **66.49 Hz**；同步低有效。
- 显示刷新率与视频素材帧率独立；视频默认 **1 fps**。2–5 fps 格式可解析，
  但不保证读卡吞吐；供数不足时保持上一完整帧并减速，音轨可能出现间歇。
- 图片 RGB24，缓存每像素 32 位；视频 RGB332，颜色精度仍为 256 色。
- 双缓存各 518400 个 32 位字，基地址 0 与 518400，总计 4147200 字节，小于片内 SDRAM 的 8 MiB。
- 每次突发 16 个字，同时整除 720 像素行、整帧和 SDRAM 的 256 字页，
  BMP 倒序行写入及缓存切换不会使突发跨页或在突发内部跳行。
- 文件列表居中显示，背景覆盖整个方屏；状态文字、字幕、缩放范围与加载动画已适配方屏。
- 频谱候选在带音轨 RVF2 视频播放期间显示八根频带柱；KEY2 短按开关。无音轨视频不显示频谱。
- 音频 RVF2 使用 12 kHz mono μ-law；每个样本重复输出 4 个 HDMI 48 kHz 采样周期。
  保留音轨时长和音高，频带低于旧 48 kHz 音轨，不宣称高保真。

基础 R2 的 720×720 显示和媒体播放已由用户实板确认。频谱候选尚未实板确认；
不同素材的 TF 卡持续吞吐仍应按实际播放效果验收。

## RV 数据约定

RVF1/RVF2 头部仍占 512 字节。宽高字段分别为 720、720，格式字段 1 代表 RGB332。
每帧真实像素 **518400 字节**，随后填充 **256 字节**，头部 frame_bytes 填写 **518656**。
填充不写入显示缓存，下一帧或音轨从下一个扇区开始。
RVF2 采样率字段为 12000；每帧样本数 12000/fps，音轨补齐至 512 字节整数倍。
默认 1 fps 时音轨 12000 样本，补齐为 12288 字节；每个音视频块共 530944 字节。

## 构建与验证

```bash
TD_BIN=/你的TD安装目录/bin/td.sh bash prj/build_tf_media720_r2.sh
bash sim/run_feature_tests.sh
python3 -m unittest discover -s sim -p 'test_*.py'
python3 tools/package_media720_spectrum.py
```

工程中间产物在 `prj/TF_MEDIA_720_R2_Runs/`。构建脚本检查工具版本、文件新鲜度和最终
Routed 时序的建立/保持违例；频谱候选打包脚本还检查资源和源码摘要。
编译、时序、RTL 仿真和实板结果分别记录在发布 JSON，不能相互代替。
本机 Icarus Verilog 可通过 `~/.local/opt/iverilog` 使用；频谱候选的按键、Goertzel 与播放器功能仿真均已通过，Python 测试可单独运行。

咖啡包从原始 1448×1086 插画生成三张等比留边海报及 720×720 的缓慢镜头运动视频，
复用原项目的原创配乐并降采样；不是实拍录像。原始素材及旧固件不覆盖。

## 发布状态

当前仓库保留实板验证通过的 `TF_MEDIA_720_R2.bit`。旧的本地频谱候选没有随当前源码发布；需要验证频谱时，应基于当前源码重新构建、通过最终布线时序并生成新的发布记录，再进行实板验收。
