# 720 首版黑屏反馈与 R2 候选

## 当前结论

用户在 2026-11-01 反馈：下载 `TF_MEDIA_720.bit` 后屏幕持续黑屏。
该首版此前只通过完整编译和静态时序，未经过实板显示验证；现记为实板失败，不能作为已验证可用固件。
现有 `TF_MEDIA_SW4_R2.bit` 是此前 640×480、用户确认成功的回退固件，两者不要混淆。

此前用户提供的“四寸、720×720、五点电容、6H 玻璃、树莓派顶针供电和耳机口”等参数，
与微雪 4inch HDMI LCD (C) 的官方描述吻合，但尚未取得本次屏幕的型号/EDID 回报。
厂家资料：https://docs.waveshare.net/4inch_HDMI_LCD_C_/

厂家公布的配置是：

```
hdmi_timings=720 0 100 20 100 720 0 20 8 20 0 0 0 60 0 48000000 6
```

首版自选 25 MHz、1000×833 总时序（约 30.012 Hz），没有按该屏公布的输入时序实现。
这是明确的适配缺口，也是黑屏的主要怀疑点；尚不能在没有实板回报的情况下确认唯一根因。

## R2 候选调整

- 原生有效区继续为 720×720，不修改 BMP/RVF2 输入格式，原 720 素材可直接复用。
- 按厂商公布数值设置像素时钟 48 MHz，总时序 940×768，水平前沿/同步/后沿为 100/20/100，
  垂直为 20/8/20，同步低有效。HDMI 自定义格式 VIC=0。
- 厂商配置文本含“60”字段，但 48 MHz ÷ 940 ÷ 768 的实际逐行频率约为 **66.489 Hz**。
  本候选复现其公布的像素时钟和消隐参数，不把计算得到的实际频率说成精确 60 Hz。
- 专用视频 PLL 包装输出 240 MHz 串行和 48 MHz 像素；旧 PLL 文件保留。
- 存储器提高至 50 MHz，SD 逻辑仍为 50 MHz；SDRAM 移相输出为 162°（9 ns）。
  沿用现有存储控制器的周期计数，保持原有刷新计数，实际刷新更频繁。
  此存储器频率及移相组合尚未实板验证，不能声称已证明稳定。
- 读缓存改为 128 字突发提高吞吐。写缓存逐次计算长度，在 256 字物理页、BMP 翻转行尾和帧尾处分段，
  防止长突发内部跳行或跨页。RGB24 图片色彩和缓存每像素 32 位表示保留。
- HDMI PCM 定时和 ACR CTS 改用实际像素时钟，保持 HDMI 48 kHz 输出；素材音轨仍为 12 kHz。
- 48 MHz 到 48 kHz 采用 1000 分频计数，避免大位宽相位累加器。
- 视频计时共用 HDMI 的 48 kHz 节拍，16 位计数即可覆盖一秒及限幅余量，
  避免 48 MHz 下原 25 位像素周期计数器溢出，并降低物理打包资源。
- EDID 触发延迟、DDC 分频、SW4 消抖及文字显示帧数同步适配。
- 完整布线发现排版与 Unicode 查找在同一周期内的路径过长；将共享字库输入寄存，
  对齐状态文字、字幕及菜单的中文/ASCII/背景控制，再将末端补偿延迟减少一级，
  保持所有图层与媒体底图总延迟一致。像素域内部仍按 48 MHz 检查。菜单增加坐标预寄存，小圆点改用等价像素区域判断；状态栏文字改用固定 18 像素字符区间译码。
- 时序分析定位到频谱横坐标除以 25 / 取余的组合路径，已做等价优化。
  但完整配置在高时钟物理打包时仍超出器件限制，本次候选 **暂时关闭频谱图层**，
  为原生画面和 HDMI 音频留出资源及时序余量。视频中的 KEY2 频谱开关暂不生效，提示文字同步去掉。
  图片/视频/音轨、字幕、文件菜单和 SW4 保留，频谱功能待显示恢复后另行优化。
- 在像素域内部长路径优化后，报告暴露 50/48 MHz 跨域路径。R2 使用独立 SDC，
  对已核对的同步器第一拍输入设置例外；保留两拍寄存器，后续级继续检查。
  异步 FIFO 的寄存 Gray 指针跨域限制为 20 ns，不对整组时钟作全局豁免。
  SDRAM 采样移相从 10 ns 调整到 9 ns，为返回数据增加建立时间；该组合仍需上板验证。

## 构建与验证

独立候选工程 `prj/TF_MEDIA_720_R2.al`，构建：

```bash
TD_BIN=/你的TD安装目录/bin/td.sh bash prj/build_tf_media720_r2.sh
bash sim/run_square_r2_tests.sh
```

候选最终报告及发布状态以 `release/TF_MEDIA_720_R2.json` 为准；未生成前不表示构建通过。
最终完整布线报告通过：SWNS +0.151 ns、STNS 0、HWNS +0.037 ns、HTNS 0。
Python 素材格式及转换器检查共 20 项通过。未经过实板验证，不据此宣称黑屏已解决。
本机缺少 Icarus，新增的行/页边界、48 MHz 音频时钟、厂家时序和两级字库逐像素等价 RTL 用例未运行。
Python 格式检查独立于 RTL 仿真，不能互相替代。

## 下载后需要确认

用 `TF_MEDIA_720_R2.bit` 做 SRAM 下载，观察是否出现菜单；不需要先重做或删除 SD 卡上的 720 素材。
屏幕应单独正确供电，沿用此前成功的 HDMI_B 接线。
若继续黑屏，需记录：是否“无信号/不支持”，是否只有背光；数码管显示；
是否为 4inch HDMI LCD (C)；在完全相同接线下烧回旧 `TF_MEDIA_SW4_R2.bit` 是否正常。
即使没有可播放素材，菜单或加载界面也应有 HDMI 输出；文件格式不符不应让显示链路永久无信号。
