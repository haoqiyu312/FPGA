# 同名 SRT 外部字幕

当前源码把视频字幕从 RTL 固定文案中分离。TF 卡根目录放 `COFFEE.RV` 与 `COFFEE.SRT`，
选择视频后自动查找同名字幕。没有字幕时正常播放视频，不再显示内置咖啡文案。
KEY3 开关字幕；KEY2 控制频谱，KEY4 控制播放/暂停，长按 KEY4 返回菜单。
SRT 不显示在媒体菜单，也不计入文件序号。子目录和 FAT 长文件名匹配尚不支持，
建议视频和字幕都使用不超过 8 个大写英文字母、数字或下划线的相同基本名。

## 准备字幕

使用 UTF-8 SRT。先在电脑运行检查和规范化工具，再复制输出文件：

```bash
python3 tools/prepare_srt.py 我的字幕.srt /目标目录/COFFEE.SRT
```

`media/COFFEE.SRT` 是可用的三段咖啡示例；复制到 TF 卡根目录后，应与 `COFFEE.RV` 同目录、同基本文件名。当前本地素材中没有 `COFFEE.RV`，需另外准备对应视频。
支持标准 `00:00:00,000 --> 00:00:03,000` 时间行和 CRLF/LF 换行。
多行文字合并为一行，初版最多 16 段，每段最多 32 个 Unicode BMP 字符，字幕文件不超过 32768 字节，
时间在 4 小时内。超限必须拆分视频/字幕；准备工具会拒绝超限、时间重叠、空文本和字库缺字。
原始 SRT 直接复制时，超过 16 段或 32 个字的内容会被截断，因此请使用工具检查。

现有 FPGA 字库仅包含英文、数字、界面和咖啡演示使用的中文，不能显示任意汉字。
UTF-8 解码与字形存储是两件事；缺字会显示为空白，准备工具会明确报出缺字。
增加未收录的汉字仍须扩充 `tools/generate_osd_font.py` 的字集并重新编译固件。
外部完整中文字体、SD 卡字形加载不属于本次实现范围。

## 调度和时间

字幕文件在视频开始前读取、解析并缓存；随后读卡通道交给视频，播放中不反复切换文件。
字幕与视频共用 FAT32 文件读取状态机，避免复制一套目录和簇链逻辑；字幕和目录支持 FAT32 碎片簇链。字幕缺失或可检测的字幕读取错误不会替代视频状态码。
SRT 的正文和时间存在统一的两块 BRAM 缓存中，视频图层只接收当前字符；共享原有 OSD 字库。

时间按实际呈现的视频帧推进，暂停和等待视频帧时保持，循环播放时回到零。
因此当前 1 fps 素材的字幕切换精度为约一秒；SRT 的毫秒字段不代表固件已有毫秒级字幕切换。
每个 HDMI 帧开头、字幕区域之前扫描缓存选段；字符在屏幕需要前一个像素取出，避免再保存一份 512 位整行缓存。

## 构建与验证

```bash
bash sim/run_subtitle_tests.sh
python3 -m unittest discover -s sim -p 'test_subtitles.py'
bash prj/build_tf_media720_r2.sh
python3 tools/package_media720_spectrum.py --srt
```

新固件只在综合、布线、最终建立与保持时序都通过后打包为 `release/TF_MEDIA_720_SRT.bit`。
`TF_MEDIA_720_R2.bit` 和 `TF_MEDIA_720_SPECTRUM.bit` 是此前产物，不能当作已包含 SRT 的固件。
本次构建最终状态见对应 JSON；没有新 JSON/bit 时，不能把源代码和仿真通过视为可下载版本。

验收时先 SRAM 下载，分别打开有/无字幕的视频；检查时间空档、KEY3、暂停恢复、视频循环，
并检查频谱、声音、菜单和图片切换。字幕候选的实板结果待用户确认。

## 本次整体优化

- 字幕复用视频 FAT32 状态机、扇区接口和簇链寄存器。
- 正文与时间表合并到一个双时钟 RAM 缓存；段数经过两级同步，加载完成经过三级同步后才允许扫描。
- 图标和频谱的颜色管线传递 5 位色号，最后恢复原 24 位颜色并注册输出，保持原像素延迟，避免逐级保存完整 RGB。
- 加载动画的十二个不重叠圆点改为并行合成，避免十二层优先选择；所有相位的像素比对一致。
- 字库按 Unicode 高字节分组，ASCII 使用连续编号计算；字体位图和所有编码的查找结果与原版一致。
- 64 采样窗频谱的递推状态收窄到 25 位；满幅任意输入的递推上界检查通过。

这些修改保留了菜单、图片缩放、转场、视频声音、频谱、字幕开关的原有功能。
资源和最终时序数据以新固件 JSON 为准；实板效果仍需 SRAM 下载验收。
