# TF 卡视频播放器首版

独立工程 `prj/TF_VIDEO.al`，器件 EG4S20BG256，顶层 `tf_video_top`。
原 `TF_IMAGE.al` 和 `release/TF_IMAGE.bit` 继续用于图片播放。

视频输入采用自定义 RVF1 格式：640×480、RGB332、1–5 帧/秒，电脑预转换，FPGA 不解码 MP4/H.264。
推荐先用 **3 帧/秒** 上板测试。现有 SPI 控制器在 50 MHz 输入下产生约 12.5 MHz 的读卡时钟，
字节握手、单扇区命令和 FAT 读取还会占用时间；5 帧/秒需要 1.536 MB/s 的纯像素吞吐，实际可能达不到。
播放器在供数不足时保留上一帧、降低实际播放速度，不跳过帧。

## 准备 TF 卡

卡使用 FAT32，保留现有文件即可，无需格式化。程序只读取根目录的 `VIDEO.RV`（FAT 短文件名）。
支持第一个 MBR FAT32 分区和无分区 FAT32、512 字节扇区、1/2/4/8/16/32/64/128 扇区的簇、
碎片化根目录和碎片化视频文件。支持一个视频文件，播放到末尾自动循环。
目前不支持 exFAT、GPT 分区解析、目录中的视频或热插卡。

在电脑上安装 ffmpeg 后，从仓库根目录执行：

```bash
python3 tools/convert_video.py input.mp4 VIDEO.RV --fps 3
```

转换器保留画面比例并补黑边，去掉音轨，输出从上到下的 RGB332 帧。
每分钟 3 fps 视频约 55 MB；颜色量化为 256 种，画质和流畅度属于功能验证级。
文件不能超过 FAT32 单文件上限；过长视频需在电脑端拆分。
转换失败不会覆盖原输出文件。转换成功后把 `VIDEO.RV` 复制到 TF 卡根目录，安全弹出，再插回断电的开发板。

没有 ffmpeg 时，可先生成 5 秒移动方块和彩条测试视频：

```bash
python3 tools/make_video_demo.py VIDEO.RV --seconds 5 --fps 3
```

外接设备播放音频。可自行从源视频导出 WAV：

```bash
ffmpeg -i input.mp4 -vn -c:a pcm_s16le AUDIO.WAV
```

该工程 HDMI 发送静音采样，不播放旧版测试音。外接音频的起播、暂停、循环和时钟没有连接 FPGA，
因此本版不保证音画同步；TF 卡供数不足导致的减速也会造成音画偏移。

## 编译和下载

沿用 TD 6.2.1 工具及许可证。脚本要求 Release 6.2.1，并检查新生成 bit 和最终时序报告。
仓库原图片工程记录的工具 Build 为 175876，本次环境提供的是 SP1 Build 178840；两者应分别验证，不能混用历史结果。

```bash
TD_BIN=/你的TD安装目录/bin/td.sh bash prj/build_tf_video.sh
```

成功后生成 `prj/TF_VIDEO_Runs/phy_1/TF_VIDEO.bit`。
只有脚本成功且时序通过的产物才能用于下载；失败构建目录中的 bit 不应使用。
如提供 `release/TF_VIDEO.bit`，它是通过最终时序检查后复制的同一文件；具体结果见本页验证记录。

先在 BitWriter 选择 **AL-LINK、PROGRAM_SRAM、1 MHz**，下载视频 bit，HDMI_B 连接显示器。
首次验证采用 SRAM 下载；确认后再考虑固化 Flash。上电完成初始化后显示视频第一帧。

- KEY1：复位读卡、缓存及播放状态，从第一帧开始。
- KEY4：暂停/继续，暂停时保留画面。首次播放前暂停会保持黑屏。
- KEY2、KEY3、SW1–SW3：本版不控制视频；按键蜂鸣器仍沿用原逻辑。
- SW5、SW6：按原板卡方式接通蜂鸣器、选择数码管。

数码管复用原布局，左边两位显示内部状态，右边两位显示目标 fps，例如 `05 OF 03`。
正常播放时 03/04/05 可能快速切换；这里的 OF 仅为复用显示布局，并非帧序号。

| 状态 | 含义 |
|---|---|
| 00 | 等待初始化 |
| 01 | 读取分区/引导扇区 |
| 02 | 搜索根目录 |
| 03 | 校验或加载视频帧 |
| 04 | 等待 SDRAM 写入完成 |
| 05 | 完整帧就绪，等待显示或暂停 |
| 10 | 分区或 FAT32 参数不支持 |
| 11 | 未找到根目录 VIDEO.RV |
| 12 | RVF1 头部无效，或文件长度不足 |
| 13 | FAT 簇链提前结束、非法或超出遍历限制 |
| 14 | 初始化、读扇区或内存握手超时 |
| 15 | 内部状态异常 |

发生错误保留上一完整帧；第一帧之前发生错误则为黑屏。修复卡后按 KEY1 重新初始化。

## 数据格式

所有多字节整数为小端。第一个扇区为 512 字节头部，其后逐帧存放 307200 字节。
每一帧恰好 600 个扇区，不跨帧共享扇区，不含 BMP 头部、调色板或音频。

| 偏移 | 字节数 | 内容 |
|---|---|---|
| 0 | 4 | ASCII `RVF1` |
| 4 | 1 | 版本 1 |
| 5 | 1 | 格式 1：RGB332 |
| 6 | 1 | 整数 fps，1–5 |
| 7 | 1 | 保留，转换器写 0 |
| 8 | 2 | 宽 640 |
| 10 | 2 | 高 480 |
| 12 | 4 | 帧数，至少 1 |
| 16 | 4 | 每帧字节数 307200 |
| 20–511 | 492 | 保留，转换器写 0 |

RGB332 字节位序为 `RRRGGGBB`，从画面左上角逐行存储。FPGA 通过重复高位扩展至 RGB888，
以每像素 32 位写入 SDRAM。两个帧缓存基地址分别为 0 和 307200（以 32 位字为单位）。

写侧仅在整个帧写入 SDRAM 后发布 toggle；读侧在垂直消隐时选择新的缓存并发出读取请求，
才把旧缓存归还给写侧。fps 和 toggle 经过跨时钟同步；缓存号按顺序交替，不直接跨域采样多位地址。
暂停仍逐显示帧重读当前缓存。加载期间显示上一帧，不显示半帧内容。

## 验证

```bash
bash sim/run_video_tests.sh
```

包括 Python 转换器测试，以及 Icarus RTL 用例：MBR/无分区 FAT32、碎片目录/文件、
逐像素颜色和帧顺序、三帧输出含循环、写提交、缓存归还前不读下一帧、缺文件、错误格式/fps、
短簇链、初始化/读卡超时、消隐换帧、暂停/继续和读请求迟迟不确认。
GitHub Actions 配置用于运行原图片回归和真实 ffmpeg 编码视频转换；本地尚未执行云端流程。
仿真使用合成扇区和内存握手，不模拟真实卡、SDRAM、电气链路或显示器。
